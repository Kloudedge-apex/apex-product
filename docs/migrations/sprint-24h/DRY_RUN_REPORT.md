## Background: why the old 12-file set was retired

The original 12-file set (now under `superseded/`) was generated against a
swarm-workspace dev baseline that included a "Reply pipeline" (Reply,
Conversation, email_event tables) which **was never promoted to apex-prod-db**.

Probing prod (apex-prod-db, PG 16.13) on 2026-05-31 confirmed:
- ✗ No `Reply` table
- ✗ No `Conversation` table
- ✗ No `email_event` table
- ✗ No `citext` or `pgcrypto` extensions
- ✓ `OutreachArtifact` table + 5 status values (DRAFT, PENDING_REVIEW, APPROVED, REJECTED, SENT)
- ✓ `evidence_event` table + trigger
- ✓ `vector` extension
- ✓ `apexadmin` role (sole app/owner role)

Migrations 005 (DROP COLUMN on missing Reply) and 009 (trigger on missing
email_event) would have failed. The 12-file set assumed a baseline that
didn't exist on prod.

The canonical 4-file set below was generated by running
`prisma migrate diff --from-url apex-prod-db --to-schema-datamodel
packages/db/prisma/schema.prisma --script` inside an Azure Container
Instance with network reach to prod. It encodes the **exact gap** between
current prod and target WS-10 schema, with no assumptions about an
intermediate baseline.

**Zero DROP statements. Zero column drops. Zero data loss risk.**

## Rollback

**003 enum extension is forward-only.** Postgres cannot drop enum values
cleanly. Code-level rollback (revert image) works to stop writing the
new values; DB carries them permanently. Acceptable per project convention.

**Everything else is reversible.** Generate a reverse diff if needed:
```
prisma migrate diff --from-schema-datamodel <ws10> --to-url <prod-pre-apply> --script
```
Take a `pg_dump` BEFORE apply on prod so we have a precise rollback target.
